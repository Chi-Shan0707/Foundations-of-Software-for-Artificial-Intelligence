# L9: Transformer 架构、多语言翻译与分词

---

## 1. Transformer 的四种架构变体

### 1.1 核心组件定义

**Encoder（编码器）**：接收整个输入序列，通过多层 Self-Attention 让每个 token 与序列中所有其他 token 交互。关键特性是**双向上下文**（Bidirectional）——计算第 3 个词时能看到第 1-2 个词和后面的词。输出是一系列特征向量，包含语义、词性、句法结构等深层信息。

**Decoder（解码器）**：逐词生成输出。关键特性是**单向/因果掩码**（Causal Masking）——生成第 n 个词时不能看到第 n+1 个词。核心模块包括 Masked Self-Attention（只看已生成历史）和 Cross-Attention（查看 Encoder 输出）。

### 1.2 三种独立架构

| 架构 | 核心能力 | 信息流动 | 典型用途 | 代表模型 |
|------|---------|---------|---------|---------|
| Encoder-Only | 理解输入内容 | 双向 | 填空、分类、提取特征 | BERT, RoBERTa |
| Decoder-Only | 续写/生成内容 | 单向（Causal/Masked） | 对话、写作、推理 | GPT, Llama, Qwen |
| Encoder-Decoder | 转换输入到输出 | 编码双向 + 解码单向 | 翻译、摘要 | T5, BART |

**Encoder-Only** 训练目标是掩码语言模型（Masked LM），类似完形填空。只保留 Transformer 编码器部分，擅长理解但不擅长生成。

**Decoder-Only** 训练目标是因果语言模型（Causal LM），即预测下一个词。去掉了 Cross-Attention，架构更简单、更易于规模化。大规模参数下涌现出通用泛化能力和零样本学习能力。目前 LLM 主流选择。

**Encoder-Decoder** 保留两者分工：Encoder 提取输入语义，Decoder 生成目标形式。适用于输入输出长度差异大的映射任务。

### 1.3 Embedding vs Encoder 的区别

Decoder-only 架构也有 Embedding，但 Embedding 只是数据的静态映射（把离散 token ID 变成连续向量），不等同于 Encoder 架构。

- Embedding = 把单词转成数字（所有模型都有）
- Encoder（架构）= 允许信息双向流动的特征提取器
- Decoder（架构）= 强制信息单向流动的生成器

Decoder-only 把"理解输入"和"生成输出"统一成同一种操作——接龙。它处理输入的方式是单向的：一边读题一边写答案，而不是反复审题。

## 2. Google 多语言翻译实验（2016）：Interlingua 与零样本翻译

### 2.1 实验背景

Google 2016 年发表 Multilingual NMT 系统（TACL），提出用单一 Encoder-Decoder 模型处理所有语言。做法：在输入句子开头加目标语言 Token（如 `<2es>` 表示译为西班牙语），然后把所有语料混在一起训练。

模型只见过：
- 葡萄牙语 → 英语
- 英语 → 西班牙语

但输入葡萄牙语并将目标 Token 设为 `<2es>` 时，模型在从未见过任何葡-西平行语料的情况下实现了高质量翻译。这就是 Zero-Shot 翻译。

### 2.2 语言混杂实验：0.5 / 0.7 的含义

实验的核心操控：在解码阶段，不使用单一目标语言 Token 向量，而是将两种语言的 Token 向量做线性插值：

$$E_{\text{mixed}} = \alpha \cdot E_{\text{langA}} + (1 - \alpha) \cdot E_{\text{langB}}$$

**意大利语 vs 西班牙语（同语系）**：
- α = 1.0：纯西班牙语
- α = 0.7：以西班牙语为主，渗透约 30% 意大利语特征
- α = 0.5：语法通顺但词汇对半混杂的"中间语言"
- α = 0.3：意大利语占主导

**英语 vs 韩语（跨语系）**：
0.5:0.5 混合时，文本呈现"局部英语、局部韩语"的交替坍塌。前半句 SVO 英语结构，后半句突然坍塌成韩语词汇和助词。即使语系完全不同，模型内部语义表征依然共享。

### 2.3 结论

这个实验证明了：

1. **隐空间连续性**：语言在模型内部不是离散孤岛，而是一片连续的几何表面。调整 α 可以在上面平滑滑行。
2. **语义与形式的分离**：Encoder 把"纯粹语义"抽象成与具体语言无关的概念向量，Decoder 根据目标语言 Token 决定输出形式。

## 3. 中文分词器（Tokenizer）

### 3.1 传统 NLP 中的分词

中文没有空格分隔，传统方法：
- **基于词典**：最大匹配法（MM, RMM）
- **基于序列标注**：将分词转化为每个字的标注问题（B/M/E/S），用 HMM 或 CRF + Viterbi 求解
- **经典工具**：Jieba（前缀词典 + HMM）、HanLP、Stanza

### 3.2 现代 LLM 的分词：BPE（Byte-Pair Encoding）

当代主流模型（Qwen, Baichuan, ChatGLM）不再用传统分词器，而是采用 BPE / SentencePiece：

1. **初始化**：将文本拆为最小单元（汉字或 UTF-8 Byte）
2. **统计迭代**：统计相邻单元共现频次，将最高频的合并为新 Token
3. **循环**：直到词表达到预设大小（如 Qwen 词表 151,936）

特点：
- **动态粒度**：高频词整体保留，低频词拆成更小单元
- **无损还原**：遇到未知符号通过 Byte 级 Token 兜底，不会出现 `[UNK]`
- **压缩率**：关键指标是 Token/汉字比。早期 LLaMA 对中文不友好（一个汉字切成 3 个 Byte Token），国产模型一个 Token 平均代表 1.5-2 个汉字
- 对拼错有鲁棒性

### 3.3 大模型的本质：频率压缩？

BPE 的核心思想就是频率压缩——高频共现的片段被压缩成单个 Token，本质上是在做语料库的熵编码。
