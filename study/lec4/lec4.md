# Lec4 并发补充说明

## `join()` 的意义

- `t1.join()`：主线程在这里等待 `t1` 结束。
- `t2.join()`：主线程在这里等待 `t2` 结束。
- 两个 `join()` 都返回后，主线程才会继续执行 `print(cnt)`。

注意：`join()` 只保证“线程都执行完再继续”，不保证“共享变量操作是线程安全的”。

## 没有 `sleep`，是否可以认为必然是 `t1` 先于 `t2`？

不可以。

- `start()` 只是把线程交给操作系统调度。
- 真正谁先运行、谁先抢到 CPU 是不确定的。
- 所以即使先写 `t1.start()`，也不代表 `t1` 必然先执行关键语句。

如果你需要严格顺序（`t1` 完全结束后再 `t2`），应写成：

```python
t1.start()
t1.join()
t2.start()
t2.join()
```

## 没有 `sleep` 时结果是 20；有 `sleep` 就一定错吗？

也不是绝对。

- 没有 `sleep`：结果经常是 20，但不是数学上保证。竞态仍然存在，只是冲突窗口更短。
- 有 `sleep`：更容易出错，但不是 100% 必错。`sleep` 拉长了“读取旧值到写回新值”的间隔，丢失更新概率显著增加。

核心结论：

- `join` 保证“结束后再打印”。
- 是否稳定得到 20，取决于是否做了线程同步（如 `Lock`），而不是是否调用 `join`。

## 协程（Coroutine）

- 协程是用户态的并发单元，常见于 `async/await` 模型。
- 协程默认在一个线程中运行，不依赖多核并行；它依靠“主动让出执行权”来切换。
- 切换通常发生在 `await` 处，所以代码逻辑要关注 `await` 前后的共享状态。

和线程对比：

- 线程切换由操作系统调度，时机相对不可控。
- 协程切换主要在 `await` 点，代码层面更容易推理。
- 协程更适合 I/O 密集场景（网络、磁盘等待），线程/进程更适合 CPU 密集并行。

补充：协程也可能出现“逻辑竞态”。

- 例如先读取共享变量，再 `await`，最后写回。
- 在 `await` 期间，其他协程可能改了该变量，导致更新丢失。
- 解决方式仍然是同步手段（如 `asyncio.Lock`）。

## 轮询（Polling）

- 轮询是“反复检查状态是否完成”的模式。
- 例如不断判断某个任务 `done()` 了没有。

优点：

- 思路直接，实现简单。

缺点：

- 需要不断检查，存在额外开销。
- 检查间隔太短会浪费资源，太长会增加响应延迟。

在协程里，轮询通常会配合短暂 `await asyncio.sleep(...)` 避免忙等；
更推荐优先使用事件驱动写法（直接 `await` 任务、`await gather(...)`、用队列/事件通知）。
