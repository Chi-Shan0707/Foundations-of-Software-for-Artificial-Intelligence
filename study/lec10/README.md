# L10 - 大模型训练

## 课堂讨论记录

### 大模型的中间运算存储

**问题**：大模型的中间运算到底存在哪里？以32B模型为例，需要多少内存存储参数？中间输入存在哪？寄存器？

**参数存储**：
- FP16/BF16: 32B × 2 bytes = 64GB 显存
- INT8量化: 32B × 1 byte = 32GB
- INT4量化: 32B × 0.5 byte = 16GB

**中间运算存储位置**：GPU HBM（高带宽显存），不是寄存器

| 存储层级 | 容量 | 存什么 |
|---------|------|--------|
| 寄存器 | KB级 | 当前正在算的单个值/向量 |
| SRAM (L1/L2 cache) | MB级 | 当前层的权重分片、中间结果 |
| HBM (显存) | 16-80GB | 全部参数 + KV Cache + 激活值 |

**推理时显存构成**（以32B模型、序列长度2048为例）：
```
总显存 ≈ 模型参数 + KV Cache + 激活值缓冲
       ≈ 64GB + 几GB + 几百MB
```

**KV Cache**：推理时的主要额外开销
- 每层每个token存 K 和 V 向量
- 层数 × 序列长度 × hidden_dim × 2(K+V) × bytes

**流动过程**：
```
HBM (存参数+KV) → SRAM (加载到片上) → 寄存器(逐元素计算) → 写回HBM
```

Flash Attention 的核心优化：让中间注意力矩阵**不写回HBM**，全程在SRAM里算完。

### Mini-batch

**定义**：训练时一次送入模型的一小批样本，而非全部数据。

**三种方式对比**：

| 方式 | batch size | 特点 |
|------|-----------|------|
| Batch GD | 全部数据 | 梯度准确，但慢、费显存 |
| SGD | 1个样本 | 快，但梯度噪声大 |
| Mini-batch | 32/64/128/... | 折中，最常用 |

**为什么用 mini-batch**：
1. 省内存：32B模型不可能一次算完所有样本
2. 梯度够用：几十个样本的梯度均值已经接近真实梯度
3. GPU并行：矩阵乘法天然适合并行，batch越大GPU利用率越高

**显存占用**：batch_size 直接影响激活值显存
```
激活值显存 ∝ batch_size × 序列长度 × hidden_dim
```

Gradient accumulation：算多个小batch的梯度累加起来，再更新一次，等效大batch但省显存。

## 课程知识点梳理

### 1. 大模型训练的核心挑战

- **参数量巨大**：模型参数规模可达T级别，导致存储和计算成本极高
- **内存占用高**：除了存储参数，训练过程中需要处理海量的上下文序列（百万级token）和梯度累积，对显存要求极高
- **计算资源需求巨大**：训练过程涉及大量的矩阵运算，需要高性能的GPU集群（如数千至数万卡）才能支撑
- **高质量数据稀缺**：可用于训练的高质量数据集有限，成为模型进一步发展的瓶颈

### 2. 参数高效微调（LoRA）

**核心思想**：针对大模型中大部分参数在微调时变化很小的特点，提出只更新一小部分参数，从而大幅降低计算量和存储需求。

**实现方式**：将需要更新的大矩阵W近似分解为两个小矩阵A和B的乘积（W ≈ A × B）。训练时仅更新A和B这两个小矩阵的参数，训练完成后将它们的乘积合并回原矩阵。

**优势**：显著减少了需要更新的参数量（从B×K减少到R×D + R×K，R远小于D和K），降低了算力消耗，同时保留了模型的微调效果。

**应用**：目前可通过Hugging Face的PEFT库等工具直接使用。

### 3. 并行训练技术

**核心思想**：将一个大的模型或训练任务拆分到多块GPU或多个机器上协同处理，以加速训练过程或运行更大规模的模型。

**Data Parallelism（数据并行）**：将一个大的batch数据拆分成多个小批次，分配给不同的GPU进行并行计算。各GPU计算完成后，梯度会在主GPU上汇总，统一更新模型参数。

**目的**：解决单机GPU算力不足的问题，是实现大规模模型训练的基础手段。
